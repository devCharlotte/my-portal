# Running Session Log

My Portal `Wellness`에 포함되는 서버 없는 러닝 기록 암호화 기록 저장소입니다.

## 보안 구조

- 비밀번호는 HTML, JavaScript, GitHub 저장소, 배포 ZIP에 포함하지 않습니다.
- 최초 실행 시 사용자가 직접 입력한 비밀번호로 브라우저 안에서 암호화 키를 생성합니다.
- PBKDF2-HMAC-SHA-256 600,000회와 무작위 16바이트 salt를 사용합니다.
- 러닝 기록 전체는 AES-256-GCM과 매 저장마다 새로운 12바이트 IV로 암호화합니다.
- IndexedDB에는 salt, IV, KDF 설정, 암호문만 저장됩니다.
- 복호화 키는 페이지가 열린 동안 메모리에만 존재하며 새로고침하거나 잠그면 폐기됩니다.
- Google API, Apps Script, Cloudflare, Supabase 및 외부 데이터베이스를 사용하지 않습니다.

## 기록 정책

- `START`부터 `STOP`까지 한 세션입니다.
- 같은 날짜에 여러 세션을 만들 수 있습니다.
- 속도 범위는 `0.3–20.0 km/h`, 경사 범위는 `0.0–16.0%`이며 모두 `0.1` 단위입니다.
- 최종 속도·경사가 기본 10초 이상 유지되면, 대기한 10초의 시간과 거리부터 해당 구간으로 확정합니다.
- 구간에는 한국시간 시작·종료 시각, 지속시간, 속도, 페이스, 경사, 거리 등이 저장됩니다.
- `STOP` 후 로그인 상태에서는 방금 완료한 현재 세션 로그를 유지하고, 로그아웃하면 모든 개인 수치와 표 행을 화면에서 즉시 제거합니다.
- 일별·주별·월별 대시보드를 로컬에서 계산하며 주·월 평균은 참여 날짜 수를 분모로 사용합니다.

## 백업

- `.runlog`: 비밀번호로 암호화된 전체 암호화 기록 저장소 백업입니다.
- `CSV`: 화면에 표시된 세션만 내보내는 평문 파일입니다.
- 브라우저 사이트 데이터를 삭제하면 IndexedDB도 지워질 수 있으므로 `.runlog` 백업을 정기적으로 만드십시오.
- 비밀번호를 잊으면 기록을 복구할 수 없습니다.

## 최초 사용

1. GitHub Pages에 배포합니다.
2. `work/wellness/treadmill-log/`을 열면 로그인 없이 빈 화면과 기능 구성을 확인할 수 있습니다.
3. `START` 또는 기록 조회 기능을 누른 뒤 본인이 정한 비밀번호를 직접 입력합니다.
4. 별도로 받은 초기 `.runlog`가 있다면 `암호화 백업 불러오기`로 가져온 뒤 해당 비밀번호로 엽니다.

## 외부에 노출되는 것

GitHub 저장소에는 화면 코드, 계산식, 암호화 방식만 공개됩니다. 실제 비밀번호, 암호화 키, 러닝 기록 및 로컬 IndexedDB 내용은 저장소에 존재하지 않습니다.

## 공개 화면과 비공개 기록

- 로그인 전에도 페이지 디자인, 빈 대시보드, 속도·경사 조작부, 표 구조를 볼 수 있습니다.
- `START`, 성장 기록 조회, CSV·암호화 백업, 설정 변경은 기록 로그인 후에만 동작합니다.
- 로그아웃 시 이전 기록의 날짜, 수치, 세션 ID, 구간 표를 DOM에서 즉시 지웁니다.
- 이 배포본은 새 IndexedDB 이름을 사용하며 이전 테스트용 `myPortal.runningVault` 데이터베이스를 최초 실행 시 삭제합니다.


## 화면 흐름

모바일 우선 반응형 구성입니다. START 및 경사·속도 조절 → 현재 세션 로그 → 현재 세션 요약과 STOP → 일·주·월 성장 대시보드 순서로 배치됩니다. 데스크톱에서는 조작부와 로그가 나란히 표시되고, 태블릿·모바일에서는 같은 순서로 세로 배치됩니다.

## v6 반응형 화면 및 기록 호환성

- 기존 암호화 저장소 이름 `myPortal.runningSessionLog.v2`와 암호화 포맷을 그대로 사용하므로 이전 버전에서 저장한 세션 뒤에 계속 기록됩니다.
- 구간 확인 시간은 새 기록부터 10초로 고정됩니다. 기존 완료 구간은 수정하지 않습니다.
- 마지막 버튼 입력 뒤의 10초는 새 속도·경사의 임시 구간으로 화면과 누적 시간·거리에 즉시 반영되며, 10초를 채우면 같은 시작 시각으로 확정됩니다.
- 현재 세션 로그 상단에는 이번 세션 이전의 완료 세션 수, 누적 기록시간·거리, 세션 평균시간·거리, 전체 평균 속도·경사를 표시합니다.
- 모바일은 경사 → 속도 → 현재 세션 로그 → 현재 세션 요약 → STOP → 성장 대시보드 순서이고, 웹에서는 조작부와 로그를 나란히 배치합니다.
- 색상과 카드 스타일은 My Portal의 핑크·블루·바이올렛 소프트 테마를 유지합니다.

## v7: 러닝머신 세션 레코더 흐름

- 러닝머신 자체의 운동 기록 화면처럼 `START → 경사/속도 조절 → 현재 세션 구간 로그 → 현재 세션 요약 → STOP` 순서로 사용합니다.
- 모바일에서는 경사가 위, 속도가 아래에 배치됩니다. 넓은 화면에서는 경사가 왼쪽, 속도가 오른쪽에 배치됩니다.
- 마지막 입력값이 10초 유지되면 첫 조절 입력 시점부터의 전환 시간을 최종 속도·경사 구간으로 묶습니다. 따라서 확정된 구간 사이에 시간·거리 공백이 생기지 않습니다.
- 현재 세션 로그 상단에는 이번 세션 이전 완료 기록의 누적 시간·거리와 세션 평균을 표시해 바로 비교합니다.
- 세션 종료 뒤에는 같은 암호화 기록을 일별·주별·월별 성장 대시보드에서 누적 관리합니다.
- 기존 `myPortal.runningSessionLog.v2` IndexedDB와 기존 암호화 포맷을 그대로 사용하므로 v2/v3 사용 기록에 이어서 저장됩니다.


## v5 UI
- 웹과 모바일에서 경사/속도 제어를 좌우 2블록으로 유지합니다.
- 각 블록은 + 버튼, 현재 숫자, - 버튼 순으로 세로 배치합니다.
- 현재 세션 구간은 카드가 아닌 고정 열 표로 표시하며 모바일에서는 가로 스크롤로 구간 지속시간을 비교합니다.
- 저장소와 암호화 포맷은 v2와 동일하여 기존 기록이 이어집니다.
